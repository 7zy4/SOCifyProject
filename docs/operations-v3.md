# تشغيل SOCify Digital Autopsy — V3

الفرع الوحيد للتنفيذ هو `socify-version-3`. النسخة قيد التطوير؛ لا تعني هذه التعليمات اجتياز قبول V3. راجع سجل التقدم ومصفوفة الرحلات قبل التشغيل التشغيلي.

## حساب مدير الفريق

التسجيل العام مغلق في الوضع التشغيلي. الحسابات الموجودة لا تتغير، ويستطيع المدير إصدار دعوات للأعضاء. لإنشاء مدير لفريق داخلي جديد من طرفية مسؤول الخادم:

```bash
python -m scripts.bootstrap_team --email manager@example.test --name "مدير التحقيق" --team "فريق التحقيق الداخلي"
```

يطلب الأمر كلمة المرور دون عرضها، ولا يضعها في history أو يعيد تعيين حساب موجود. استخدم بريد الشركة الفعلي عند التشغيل الداخلي، واضبط `SOCIFY_DATABASE` للقاعدة المعتمدة قبل الأمر. في التطوير يحمّل الأمر مفاتيح Codespaces المحفوظة؛ في الإنتاج يلزم إعداد مفاتيح وبيئة الشركة مسبقًا. لا تحذف ملف المفاتيح أو تغيّره للوصول إلى قاعدة موجودة.

للتجربة بعد تحميل البيئة المناسبة:

```bash
python run.py
```

افتح `/cases` بعد الدخول. أنشئ قضية بالعنوان والسبب والهدف، ثم استخدم أقسامها السياقية. لا تستخدم `/lab` أو `/scores` أو APIs تدريب عامة؛ متقاعدة في وضع التشغيل. توافق التدريب داخل الاختبارات فقط، مع استمرار اختبارات V2 لتجنب فقد السلوك/البيانات التاريخية.

## حدود البيانات

Codespaces لتطوير الكود والبيانات الاصطناعية فقط. نشر وتحليل بيانات الشركة يكون داخل بنيتها المعتمدة. حظر APIs الخارجية في التطبيق لا يغني عن منع خروج الشبكة من الحاويات والعمال ومحرك التقرير في بيئة الشركة.

لا تنقل سجلات شركة أو عينات أو نسخ قاعدة أو تقارير إلى GitHub أو إلى أدلة الاختبارات. تتبع نتيجة فحوص العزل والأداء على بيئة ممثلة؛ لا تُعامل نتائج fixture صغيرة كاختبار تحميل إنتاجي.
