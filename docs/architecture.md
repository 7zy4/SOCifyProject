# هندسة منصة التحقيق

SOCify تطبيق Flask لإدارة القضايا والتحقيق في الحوادث وتحليل الأدلة وإصدار التقارير. يبدأ الاستخدام من المراقبة أو إدارة القضايا. تجمع المراقبة التنبيهات داخل نطاق العضوية ومساحة العمل والدفعات المصرح بها، ثم تُجرى عمليات الاستيراد والبحث والتحليل والتوثيق في نطاق قضية محددة. قاعدة البيانات الحالية SQLite؛ قابلية نشرها وحدود الحمل تعتمد على البيئة والحجم ونتائج القياس الفعلية.

```mermaid
flowchart TD
    UI[واجهة التحقيق العربية والإنجليزية] --> WEB[Flask والصلاحيات والجلسات وحماية النماذج]
    WEB --> CASE[القضية والأعضاء والمهام]
    CASE --> IMPORT[مهام الاستيراد الدائمة]
    IMPORT --> EVIDENCE[الأصول والسجلات وبصمات الأدلة]
    EVIDENCE --> INVESTIGATION[المؤشرات والفرضيات والخط الزمني والاستجابة]
    INVESTIGATION --> JOBS[مهام التحليل والتقارير]
    JOBS --> WORKER[عامل المعالجة]
    WORKER --> ANALYSIS[تحليل معزول بلا شبكة]
    ANALYSIS --> REPORT[نسخ التقارير والمراجعة والاعتماد]
    CASE --> AUDIT[التدقيق وسلسلة الحيازة]
    EVIDENCE --> AUDIT
    REPORT --> AUDIT
```

## تنظيم المنطق

| الملفات | المسؤولية |
| --- | --- |
| `socify/__init__.py`, `config.py`, `ui.py` | إنشاء التطبيق والإعدادات وصفحات مساحة العمل |
| `auth.py`, `security.py`, `operational.py` | الهوية والجلسات وMFA والصلاحيات ونطاق القضايا |
| `cases.py`, `autopsy_api.py`, `teams.py` | القضايا والسجلات والأعضاء والإسناد |
| `autopsy_ingestion.py`, `autopsy_pipeline.py`, `import_worker.py` | الاستيراد ومعالجة السجلات والمهام القابلة للاستئناف |
| `autopsy_chronology.py`, `autopsy_investigation.py`, `autopsy_workflow.py` | التسلسل الزمني والفرضيات ونطاق التحقيق وتوثيق القرارات |
| `autopsy_soc.py`, `autopsy_pipeline.py` | قائمة المراقبة والقنوات والبحث والترقيم ونطاق وصول القضايا والدفعات |
| `autopsy_email.py` | تحليل MIME الساكن لرسائل EML المحجورة وحفظ النتيجة المرتبطة بالدليل |
| `autopsy_samples.py`, `autopsy_detection.py`, `autopsy_yara.py` | عينات الأدلة والكشف والتحليل المحلي |
| `autopsy_reports.py`, `autopsy_report_render.py`, `report_brand.py` | اللقطات الثابتة والمراجعة وتوليد صيغ التقارير |
| `analysis_transport.py`, `analysis_sandbox.py`, `autopsy_worker.py` | اتصال المعالجة المعزولة وحدود الموارد وحالة المهام |
| `db.py`, `schema.py`, `autopsy_schema.py` | اتصالات SQLite والترحيل وسلامة العلاقات |

## سلامة التحقيق

- يتحقق الخادم من مساحة العمل وعضوية القضية والصلاحية لكل قراءة وتعديل وتصدير؛ إخفاء عنصر في الواجهة ليس تصريحًا.
- تُحفظ الأدلة الأصلية وبصماتها، وتُسجّل تغييرات التحقيق كإصدارات وحركات حيازة وتدقيق.
- تُجهّز التقارير من لقطة ثابتة مع إصدار المصدر وسياسة المشاركة؛ لا تُعاد صياغة نسخة معتمدة عند تغير القضية.
- خدمة التحليل منفصلة عن قاعدة البيانات ومفاتيح التشفير، بلا شبكة، مع قيود للعمليات والذاكرة والوقت. غياب العزل المطلوب يمنع التنفيذ.
- لا ينفذ المتصفح نصوص الأدلة المستوردة. تُعرض القيم كنصوص، وتظل الأدلة والمعرفات والأوقات محفوظة دون ترجمة محتواها.
- الاستيراد والتحليل والتقارير يستخدمون مهام دائمة مع حالات ومحاولات وإلغاء واستعادة، ولا يعتمدون على بقاء طلب HTTP مفتوحًا.

## توافق البيانات

بعض منطق الإصدارات السابقة باقٍ لقراءة البيانات القديمة وترحيلها وللتحقق من التوافق. المسارات العامة للتدريب متقاعدة في الوضع التشغيلي، ولا تُعرض كهوية للمنصة أو قدرات تشغيلية. لا تُحذف الجداول أو الوحدات التي تعتمد عليها الترحيلات وسجلات القضايا القديمة لمجرد تقاعد واجهتها.

لإعداد النشر والمفاتيح والعامل المعزول والنسخ الاحتياطي راجع [دليل التشغيل](operations-v3.md)، ولضوابط الأمان راجع [دليل الأمان](security-guide.md).

## واجهة مركز العمليات

تستخدم الواجهة `templates/app.html` و`static/soc-workbench.js` وهيكل تنقل ثابتًا متوافقًا مع العربية والإنجليزية. قنوات المراقبة مشتقة من حالة القضية المرتبطة، ولا تضيف حالات إغلاق تتجاوز المراجعة. الأدوات المستقلة تحتفظ بـcase_id في URL؛ لا تختار قضية بالنيابة عن المستخدم. الأعداد والقوائم تستبعد القضايا ذات الدفعات غير المصرح بها، ولا تكتفي بإخفاء صفوفها في المتصفح.

تحتفظ أداة البريد بالأصل في حجر العينات المشفر الحالي، وتتحقق من البصمة قبل تحليل MIME. الرؤوس وروابط الرسالة بيانات غير موثوقة لا تُنفذ ولا تُفتح. النتيجة سجل analysis مرتبط بالدليل وتدخل لقطة التقرير. الواجهة لا تدّعي اتصال EDR حيًا أو sandbox ديناميكيًا.

زر التقرير الفوري يستخدم مسار snapshots والطابور الموجود، مع سياسة full أو metadata_only_v1 بحسب إذن تنزيل الأدلة. يبقى توليد الصيغ والتحقق والاعتماد منفصلًا عن إنشاء النسخة.
