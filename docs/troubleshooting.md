# استكشاف الأعطال

## ابدأ من النتيجة الظاهرة

- احتفظ برسالة الخطأ ومعرّف الطلب ووقت حدوثه.
- تحقق من القضية والحساب والمصدر المقصود قبل إعادة المحاولة.
- لا تشارك كلمات المرور أو مفاتيح المصادر أو محتوى السجلات الحساسة.

| المشكلة | الإجراء |
|---|---|
| تعذر الدخول أو انتهاء الجلسة | افتح نموذج الدخول من جديد؛ تحقق من القاعدة الفعلية وثبات مفتاح الجلسة والوقت |
| `MFA_KEY_MISMATCH` | استعد مفتاح الاعتماد الصحيح؛ لا تحذف MFA أو تغير المفاتيح عشوائيًا |
| لا تظهر قضية أو بيانات | راجع مساحة الفريق والعضوية والصلاحيات ونطاق دفعة الاستيراد |
| تعذر تنزيل الأصل | راجع صلاحية تنزيل الأدلة؛ صلاحية القراءة وحدها لا تكفي |
| الاستيراد في الانتظار | افحص `import-worker` والطابور والقاعدة ومفتاح فك أدلة الرفع |
| الاستيراد مرفوض | اقرأ خطأ الدفعة؛ صحح الصيغة أو UTF-8 أو الحقول أو المنطقة الزمنية أو الحد المتجاوز |
| مصدر HTTPS يفشل | راجع العنوان وallowlist وDNS العام وشهادة TLS ومسار الخروج وحد الرد |
| نجاح الاستيراد دون تنبيه | راجع البيانات وتغطية القواعد وحالتها؛ ليس كل سجل سببًا لتنبيه |
| التحليل أو التقرير لا يكتمل | افحص خدمة `analysis` والعامل والمقبس؛ جاهزية الواجهة وحدها لا تثبت جاهزية التحليل |
| خطأ `DB locked` | افحص المعاملات الطويلة وعدد العمال ومساحة القرص وتوافق التخزين مع WAL |
| تعذر اعتماد التقرير | تحقق من اكتمال ملفاته ومطابقته لحالة القضية، ومن وجود مراجع آخر أو استثناء مدير مسبب |
| تعذر إغلاق القضية | افتح قائمة المتطلبات: الأدلة والسبب الجذري والتحقق والمهام والتصعيدات والمعالجة والتقرير المعتمد |
| نسبة الأداء فارغة | راجع العينة والفترة والسياسة والتاريخ المتاح؛ غياب القياس ليس صفرًا |
| خطوة تحتاج موافقة | اطلب موافقة صاحب الصلاحية؛ لا تتجاوزها بتعديل القاعدة |
| تقنية ATT&CK غير موجودة | راجع الكتالوج النشط أو استورد ملف STIX محليًا موثوقًا |
| Codespace لا يفتح | افحص المنفذ من Ports وأبقه Private؛ استخدم [المشغّل الموثق](codespaces.md) |

## فحص الخدمات

```bash
curl -fsS http://127.0.0.1:5000/health/ready
docker compose ps
docker compose logs --tail 100 analysis autopsy-worker import-worker playbook-worker
```

- في التشغيل المحلي تظهر رسائل التطبيق في طرفية `python run.py`.
- لفحص حساب وقاعدة دون تغييرهما:

```bash
python -m scripts.bootstrap_team --email owner@example.com --status
```

- تعليمات استعادة الحساب في [Codespaces](codespaces.md#استعادة-الدخول).
- لا تُعد إرسال طلب نجح قبل تحديث الصفحة؛ افحص النتيجة الحالية لتجنب عمل مكرر.

## رفض CSRF

- الرمز يُنشأ تلقائيًا؛ لا يحتاج المستخدم كتابته.
- افتح نموذجًا جديدًا من عنوان الموقع نفسه، واسمح بملفات الارتباط.
- لا تعطل CSRF لحل مشكلة دخول.

| رمز التشخيص | الإجراء |
|---|---|
| `TOKEN_MISSING` | افتح النموذج الحالي من جديد |
| `SESSION_MISSING` | اسمح بملفات الارتباط وافتح Ports في نافذة مستقلة |
| `TOKEN_EXPIRED` | أعد الإرسال من نموذج جديد |
| `TOKEN_INVALID` | تحقق من ثبات المفتاح وعدم تشغيل خادم قديم |
| `TOKEN_MISMATCH` | استخدم نموذجًا جديدًا من جلسة الموقع نفسها |
| `REFERRER_MISSING` | افحص إضافة المتصفح أو السياسة التي تحذف Referer |
| `REFERRER_MISMATCH` | طابق عنوان الموقع والمنفذ وإعداد الوكيل؛ لا توسع الثقة عشوائيًا |
| `VALIDATION_FAILED` | احفظ معرّف الطلب وراجع إعداد الخادم |

- لتجميع سجل محلي بعد إيقاف الخادم السابق:

```bash
python run.py 2>&1 | tee /tmp/socify-login-debug.log
```

- ابحث من طرفية ثانية:

```bash
rg 'csrf_rejected' /tmp/socify-login-debug.log
```

- يحتوي سطر التشخيص على السبب ومعرّف الطلب؛ لا تنشر بقية سجل التشغيل قبل مراجعته.
- [دليل التشغيل](operations.md) · [دليل الأمان](security-guide.md).
