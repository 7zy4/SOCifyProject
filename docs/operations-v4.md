# تشغيل SOCify V4 وتجربته

V4 مبني مباشرة على رأس V3 `7851d3b329ea4aecdff5a3077cd914a22055a34b` في فرع مستقل `V4`. لا يغيّر هذا الفرع V3 أو main. [برومت التنفيذ](v4-execution-prompt.md) محفوظ مع المصدر، و[دليل السيناريو](v4-demo-walkthrough.md) يوضح النتائج المتوقعة.

## التشغيل المحلي من المصدر

يتطلب Python 3.12+ وDocker. لا توجد كلمات مرور ثابتة أو حسابات تجريبية تلقائية. أوامر التجربة التالية تنشئ قاعدة مستقلة وفريقًا وهميًا فقط؛ ترفض التهيئة مجلدًا موجودًا وترفض التشغيل في الإنتاج.

```bash
git clone --branch V4 https://github.com/7zy4/SOCifyProject.git
cd SOCifyProject
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
docker build --target analysis -t socify-v4-analysis .
bash scripts/start_v4_analysis.sh
export SOCIFY_ANALYSIS_SOCKET=/tmp/socify-v4-dev-analysis-ipc/analysis.sock
python -m scripts.prepare_v4_demo --directory instance/v4-demo
python -m scripts.run_v4_demo --directory instance/v4-demo --port 5000
```

افتح `http://127.0.0.1:5000`. بيانات الدخول المولّدة موجودة في `instance/v4-demo/accounts.json`؛ لا يطبع الأمر كلمات المرور في سجل التنفيذ. في Codespaces استخدم عنوان المنفذ 5000 من تبويب Ports. لا يحتاج Codespaces إلى إنشاء مشروع أو حساب جديد. عند استخدام حزمة التجربة الخاصة المسلّمة، فكّها داخل المستودع بحيث يظهر `instance/v4-demo/manifest.json`، وتجاوز أمر `prepare_v4_demo` لأن القاعدة جاهزة مسبقًا. حسابات الحزمة هي الحسابات الواردة في دليل الدخول الخاص بها؛ التهيئة من الصفر تولّد كلمات مرور جديدة.

توجد أمثلة JSON وCSV وEML وعينة نصية آمنة في `instance/v4-demo/fixtures/`. احتفظ بملف `runtime.env` مع `socify.db`: المفاتيح ضرورية لفك تشفير الأدلة والتقارير. المجلد وحزمة التجربة الخاصة لا يُرفعان إلى Git. حزم المصدر العامة لا تتضمنهما.

تعمل مهام الاستيراد والتحليل والتقارير عبر العاملين المحليين أثناء تشغيل `run_v4_demo`. خدمة التحليل منفصلة، بلا شبكة، بملفات للقراءة فقط وtmpfs وقيود ذاكرة وعمليات. الساندبوكس تحليل ساكن: بصمات، ترويسات الملفات، نصوص وقواعد YARA. لا ينفذ ملفات ولا يزور عناوين URL أو IP. عند توقف الخدمة تُظهر المهام حالة فشل/محاولة فعلية، ولا تنتج نتيجة نجاح بديلة.

## القضايا والاعتماد والنطاق

1. بعد الدخول تظهر `/cases`. يرى المحلل قضاياه وعضوياته، ويرى المدير قضايا مساحة العمل.
2. طلب القضية الجديدة يبدأ بانتظار المدير، حتى إن أنشأه المدير. يظهر سبب الطلب وهدفه، وتبقى أدواته مقفلة في API والواجهة.
3. يفتح المدير الطلب ويختار الاعتماد أو الرفض مع السبب. يتطلب القرار `cases.override` مع دور مدير/مسؤول. القرار نهائي بإصدار متفائل داخل معاملة SQLite، ويسجل في التاريخ والحيازة والتدقيق. لطلب مرفوض يمكن إنشاء طلب جديد مصحح.
4. اختر قضية معتمدة واحدة أو قضيتين مرتبطتين من صفحة القضايا. الاختيارات غير المرتبطة تتعطل في الواجهة ويرفضها الخادم أيضًا. يستطيع المدير إنشاء علاقة بسبب موثق من ملخص القضية.
5. اختيار القضية النشطة في الأعلى يغيّر وجهة العمل، مع بقاء النطاق المزدوج محددًا. كل عملية استيراد أو تحليل أو كتابة أو تقرير تخص قضية واحدة. تجمع المراقبة تنبيهات القضايا المختارة فقط؛ القنوات الرئيسية/التحقيق/المغلقة تبقى مستقلة.
6. تُفحص العضوية والاعتماد والعلاقة وحدود دفعات الاستيراد في كل طلب. لا تضيف معاملات URL قضايا للنطاق. يُمسح النطاق كاملًا عند فقدان صلاحية إحدى القضيتين أو عند تبديل الحساب.

ترحيل قاعدة V3 القائمة يمنح القضايا القائمة اعتمادًا موروثًا `v3_migration` مرة واحدة، دون تغيير أدلتها أو تقاريرها. كل استعادة كبسولة تنشئ طلبًا جديدًا يحتاج اعتمادًا محليًا؛ لا تنقل سلطة اعتماد أجنبية. قاعدة العمل غير التجريبية تستمر عبر `python run.py` أو نشر Gunicorn كما في [دليل التشغيل المؤسسي](operations-v3.md)، دون تفعيل `SOCIFY_DEMO_MODE`.

## حسابات الفريق وصلاحياته

| الحساب | الدور | ما يستطيع فعله | الحدود |
| --- | --- | --- | --- |
| `manager@demo.socify.test` | soc_manager | اعتماد القضايا وربطها وإسناد الفريق والدفعات، إدارة قواعد الكشف والإثراء والكتيبات، التحقيق والتقارير | ضمن مساحة عمله؛ الأدوات تتطلب اعتماد القضية واختيارها؛ ليس مسؤول منصة عامًّا |
| `analyst@demo.socify.test` | l1_analyst | إنشاء طلب، فرز وتحقيق، رفع أدلة، بحث السجلات، تحليل ساكن، مؤشرات ومهام وتقرير وتصدير | القضايا المسندة/العضوية فقط؛ لا اعتماد قضايا أو إدارة فريق أو نشر قواعد |
| `responder@demo.socify.test` | l2_responder | أدوات المحلل، استلام تصعيد L2، توثيق الاستجابة والتحقق والتصحيح | نفس حدود عضوية القضايا؛ لا اعتماد قضايا أو إدارة عامة |
| `reviewer@demo.socify.test` | reviewer | قراءة القضايا المسندة، الملاحظات، مراجعة واعتماد تقارير الآخرين | لا رفع عينات أو تعديل التحقيق أو إنشاء طلب؛ لا تنزيل أصول/عينات أو ملفات التقارير الكاملة دون صلاحية تنزيل الأدلة |

تشترك L1 وL2 في صلاحيات أدوات التحقيق الأساسية الحالية، وتختلف مسؤولياتهما ومسارات التصعيد. لا يُمنح L2 إدارة عامة لمجرد مستواه. تعرض صفحة الفريق الصلاحيات الفعلية القابلة للتقليل ضمن حدود الدور. اعتماد تقرير ذاتي يحتاج استثناء المدير وسببه وفق ضوابط V3.

أيقونة التبديل أعلى الصفحة تفتح حسابات هذه القاعدة الوهمية فقط. التبديل ينهي جلسة المصدر، وينشئ جلسة جديدة، ويعيد المستخدم إلى القضايا دون نطاق سابق. يلزم الدخول أولًا؛ لا توجد قائمة حسابات عامة. في التشغيل العادي تنهي الأيقونة الجلسة لتمكين تسجيل الدخول بحساب آخر. يرفض التطبيق تفعيل وضع التجربة في الإنتاج.

## عقود V4

| المسار | العقد |
| --- | --- |
| `GET/POST /api/investigation-selection` | قراءة/تعيين `case_ids`، عنصر أو عنصران فريدان ومعتمدان؛ تحقق الربط والعضوية بالخادم |
| `POST /api/cases/{id}/approval` | `decision`, `version`, `reason`؛ مدير مع `cases.override`؛ تعارض القرار 409 |
| `POST /api/cases/{id}/relationships` | `related_case_id`, `reason`؛ قضيتان مختلفتان معتمدتان في المساحة نفسها |
| `GET /api/demo/accounts` | حسابات سجل التجربة للمستخدم المصرح فقط؛ خارج التجربة `enabled:false` |
| `POST /api/demo/switch` | `user_id` من سجل التجربة نفسه، مع CSRF وتدوير الجلسة ومسح النطاق |

الأخطاء الأساسية: `CASE_APPROVAL_REQUIRED`=409، `CASE_SELECTION_REQUIRED`=403، `CASES_NOT_RELATED`=422، `CASE_NOT_FOUND`=404، `REVIEW_CONFLICT`=409. يشمل القيد مسارات cases/incidents القديمة وعمليات إسناد الفريق التي تمرر معرف القضية في الجسم. مهام الخلفية تتحقق من الاعتماد والعضوية وصلاحيات الدفعات، ولا تعتمد على جلسة متصفح قد تكون انتهت. العقد الكامل في [OpenAPI](api/openapi.yaml).

## هوية العرض

التصميم يستخدم لوحات حبر داكنة وأصفر إشارة وحدودًا واضحة وظلالًا قصيرة وتكتشر نقاط في التنقل، مع أسطح نظيفة للقراءة والتحقيق. مصدر الألوان هو `static/design-tokens.json` وتُولد منه `static/tokens.css`. CSS الخاص بالهوية في `comic-workspace.css`، وخطوط Almarai وIBM Plex Sans محلية. الوضع الابتدائي داكن مع استمرار خيارات الفاتح وحسب النظام. لا توجد أسماء شخصيات أو رسومها داخل المنتج.
