# تشغيل SOCify V4 وتجربته

V4 مبني مباشرة على رأس V3 `7851d3b329ea4aecdff5a3077cd914a22055a34b` في فرع مستقل `V4`. لا يغيّر هذا الفرع V3 أو main. [دليل السيناريو](v4-demo-walkthrough.md) يوضح النتائج المتوقعة.

## التشغيل المحلي من المصدر

في Codespaces استخدم [خطوات إصلاح البيئة وتشغيل V4](codespaces.md#v4-إصلاح-no_pubkey-وتشغيل-التجربة)، ثم الأمر الموحد `bash scripts/try_v4_demo.sh` بعد اكتمال Rebuild Container. بيانات الدخول تُولّد في Codespace الخاص بك داخل `instance/v4-demo/accounts.json`.

يتطلب Python 3.12+ وDocker. لا توجد كلمات مرور ثابتة أو حسابات تجريبية تلقائية. أوامر التجربة التالية تنشئ قاعدة مستقلة وفريقًا وهميًا فقط؛ ترفض التهيئة مجلدًا موجودًا وترفض التشغيل في الإنتاج.

```bash
git clone --branch V4 https://github.com/7zy4/SOCifyProject.git
cd SOCifyProject
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
docker build --target analysis -t socify-v4-analysis .
bash scripts/start_v4_analysis.sh
export SOCIFY_ANALYSIS_SOCKET=/tmp/socify-v4-dev-analysis-ipc/analysis.sock
python -m scripts.prepare_v4_demo --directory instance/v4-demo
python -m scripts.run_v4_demo --directory instance/v4-demo --port 5000
```

افتح `http://127.0.0.1:5000`. بيانات الدخول المولّدة موجودة في `instance/v4-demo/accounts.json`؛ لا يطبع الأمر كلمات المرور في سجل التنفيذ. في Codespaces استخدم عنوان المنفذ 5000 من تبويب Ports. لا يحتاج Codespaces إلى إنشاء مشروع أو حساب جديد. عند استخدام حزمة التجربة الخاصة المسلّمة، فكّها داخل المستودع بحيث يظهر `instance/v4-demo/manifest.json`، وتجاوز أمر `prepare_v4_demo` لأن القاعدة جاهزة مسبقًا. حسابات الحزمة هي الحسابات الواردة في دليل الدخول الخاص بها؛ التهيئة من الصفر تولّد كلمات مرور جديدة.

توجد أمثلة JSON وCSV وEML وعينة نصية آمنة في `instance/v4-demo/fixtures/`. احتفظ بملف `runtime.env` مع `socify.db`: المفاتيح ضرورية لفك تشفير الأدلة والتقارير. المجلد وحزمة التجربة الخاصة لا يُرفعان إلى Git. حزم المصدر العامة لا تتضمنهما.

تعمل مهام الاستيراد والتحليل والتقارير عبر عمال import وautopsy وplaybook المحليين أثناء تشغيل `run_v4_demo`. خدمة التحليل منفصلة، بلا شبكة، بملفات للقراءة فقط وtmpfs وقيود ذاكرة وعمليات. الساندبوكس تحليل ساكن: بصمات، ترويسات الملفات، نصوص وقواعد YARA. لا ينفذ ملفات ولا يزور عناوين URL أو IP. عند توقف الخدمة تُظهر المهام حالة فشل/محاولة فعلية، ولا تنتج نتيجة نجاح بديلة.

## القضايا والاعتماد والنطاق

1. بعد الدخول تظهر `/cases`. يرى المحلل قضاياه وعضوياته، ويرى المدير قضايا مساحة العمل.
2. طلب القضية الجديدة يبدأ بانتظار المدير، حتى إن أنشأه المدير. يظهر سبب الطلب وهدفه، وتبقى أدواته مقفلة في API والواجهة.
3. يفتح المدير الطلب ويختار الاعتماد أو الرفض مع السبب. يتطلب القرار `cases.override` مع دور مدير/مسؤول. القرار نهائي بإصدار متفائل داخل معاملة SQLite، ويسجل في التاريخ والحيازة والتدقيق. لطلب مرفوض يمكن إنشاء طلب جديد مصحح.
4. اختر قضية معتمدة واحدة أو قضيتين مرتبطتين من صفحة القضايا. الاختيارات غير المرتبطة تتعطل في الواجهة ويرفضها الخادم أيضًا. يستطيع المدير إنشاء علاقة بسبب موثق من ملخص القضية.
5. اختيار القضية النشطة في الأعلى يغيّر وجهة العمل، مع بقاء النطاق المزدوج محددًا. كل عملية استيراد أو تحليل أو كتابة أو تقرير تخص قضية واحدة. تجمع المراقبة تنبيهات القضايا المختارة فقط؛ القنوات الرئيسية/التحقيق/المغلقة تبقى مستقلة.
6. تُفحص العضوية والاعتماد والعلاقة وحدود دفعات الاستيراد في كل طلب. لا تضيف معاملات URL قضايا للنطاق. يُمسح النطاق كاملًا عند فقدان صلاحية إحدى القضيتين أو عند تبديل الحساب.

ترحيل قاعدة V3 القائمة يمنح القضايا القائمة اعتمادًا موروثًا `v3_migration` مرة واحدة، دون تغيير أدلتها أو تقاريرها. كل استعادة كبسولة تنشئ طلبًا جديدًا يحتاج اعتمادًا محليًا؛ لا تنقل سلطة اعتماد أجنبية. قاعدة العمل غير التجريبية تستمر عبر `python run.py` أو نشر Gunicorn كما في قسم النشر المؤسسي أدناه، دون تفعيل `SOCIFY_DEMO_MODE`.

| الحساب | الدور | ما يستطيع فعله | الحدود |
| --- | --- | --- | --- |
| `manager@demo.socify.test` | soc_manager | اعتماد القضايا وربطها وإسناد الفريق والدفعات، إدارة قواعد الكشف والإثراء والكتيبات، التحقيق والتقارير | ضمن مساحة عمله؛ الأدوات تتطلب اعتماد القضية واختيارها؛ ليس مسؤول منصة عامًّا |
| `analyst@demo.socify.test` | l1_analyst | إنشاء طلب، فرز وتحقيق، رفع أدلة، بحث السجلات، تحليل ساكن، مؤشرات ومهام وتقرير وتصدير | القضايا المسندة/العضوية فقط؛ لا اعتماد قضايا أو إدارة فريق أو نشر قواعد |
| `responder@demo.socify.test` | l2_responder | أدوات المحلل، استلام تصعيد L2، توثيق الاستجابة والتحقق والتصحيح | نفس حدود عضوية القضايا؛ لا اعتماد قضايا أو إدارة عامة |
| `reviewer@demo.socify.test` | reviewer | قراءة القضايا المسندة، الملاحظات، مراجعة واعتماد تقارير الآخرين | لا رفع عينات أو تعديل التحقيق أو إنشاء طلب؛ لا تنزيل أصول/عينات أو ملفات التقارير الكاملة دون صلاحية تنزيل الأدلة |

تشترك L1 وL2 في صلاحيات أدوات التحقيق الأساسية الحالية، وتختلف مسؤولياتهما ومسارات التصعيد. لا يُمنح L2 إدارة عامة لمجرد مستواه. تعرض صفحة الفريق الصلاحيات الفعلية القابلة للتقليل ضمن حدود الدور. اعتماد تقرير ذاتي يحتاج استثناء المدير وسببه وفق ضوابط V3.

أيقونة التبديل أعلى الصفحة تفتح حسابات هذه القاعدة الوهمية فقط. التبديل ينهي جلسة المصدر، وينشئ جلسة جديدة، ويعيد المستخدم إلى القضايا دون نطاق سابق. يلزم الدخول أولًا؛ لا توجد قائمة حسابات عامة. في التشغيل العادي تنهي الأيقونة الجلسة لتمكين تسجيل الدخول بحساب آخر. يرفض التطبيق تفعيل وضع التجربة في الإنتاج.

## عقود V4

| المسار | العقد |
| --- | --- |
| `GET/POST /api/investigation-selection` | قراءة/تعيين `case_ids`، عنصر أو عنصران فريدان ومعتمدان؛ تحقق الربط والعضوية بالخادم |
| `POST /api/cases/{id}/approval` | `decision`, `version`, `reason`؛ مدير مع `cases.override`؛ تعارض القرار 409 |
| `POST /api/cases/{id}/relationships` | `related_case_id`, `reason`؛ قضيتان مختلفتان معتمدتان في المساحة نفسها |
| `GET /api/demo/accounts` | حسابات سجل التجربة للمستخدم المصرح فقط؛ خارج التجربة `enabled:false` |
| `POST /api/demo/switch` | `user_id` من سجل التجربة نفسه، مع CSRF وتدوير الجلسة ومسح النطاق |

الأخطاء الأساسية: `CASE_APPROVAL_REQUIRED`=409، `CASE_SELECTION_REQUIRED`=403، `CASES_NOT_RELATED`=422، `CASE_NOT_FOUND`=404، `REVIEW_CONFLICT`=409. يشمل القيد مسارات cases/incidents القديمة وعمليات إسناد الفريق التي تمرر معرف القضية في الجسم. مهام الخلفية تتحقق من الاعتماد والعضوية وصلاحيات الدفعات، ولا تعتمد على جلسة متصفح قد تكون انتهت. العقد الكامل في [OpenAPI](api/openapi.yaml).

## هوية العرض

التصميم يستخدم لوحات حبر داكنة وأصفر إشارة وحدودًا واضحة وظلالًا قصيرة ونقاطًا زخرفية في التنقل، مع أسطح نظيفة للقراءة والتحقيق. مصدر الألوان هو `static/design-tokens.json` وتُولد منه `static/tokens.css`. CSS الخاص بالهوية في `comic-workspace.css`. الخطوط المحلية هي Cairo وIBM Plex Sans Arabic وTajawal للعربية، وBangers وIBM Plex Sans وComic Neue للإنجليزية، وJetBrains Mono للشيفرة. الوضع الابتدائي داكن مع استمرار خيارات الفاتح وحسب النظام. لا توجد أسماء شخصيات أو رسومها داخل المنتج.

مراجع استلهام: [واجهة dashboard منشورة](https://github.com/tatrong/batpanel-dashboard)، [مكونات الطباعة المصورة](https://kaboom-ui-kit.pages.dev/). مراجع سير العمل: [LetsDefend](https://help.letsdefend.io/en/articles/8742685-what-is-letsdefend)، [توثيق الاستجابة](https://letsdefend.io/blog/incident-response-edition-documentation)، [تحقيق Elastic](https://www.elastic.co/docs/solutions/security/investigate). استُخلصت مبادئ عرض وتشغيل، دون نسخ أصول أو إضافة اعتمادية تصميمية خارجية.


## إدارة التشغيل المستمر

## حساب مدير الفريق

التسجيل العام مغلق في الوضع التشغيلي. الحسابات الموجودة لا تتغير، ويستطيع المدير إصدار دعوات للأعضاء. لإنشاء مدير لفريق داخلي جديد من طرفية مسؤول الخادم:

```bash
python -m scripts.bootstrap_team --email manager@example.test --name "مدير التحقيق" --team "فريق التحقيق الداخلي"
```

يطلب الأمر كلمة المرور دون عرضها، ولا يضعها في history أو يعيد تعيين حساب موجود. استخدم بريد الشركة الفعلي عند التشغيل الداخلي، واضبط `SOCIFY_DATABASE` للقاعدة المعتمدة قبل الأمر. في التطوير يحمّل الأمر مفاتيح Codespaces المحفوظة؛ في الإنتاج يلزم إعداد مفاتيح وبيئة الشركة مسبقًا. لا تحذف ملف المفاتيح أو تغيّره للوصول إلى قاعدة موجودة.

لفحص الحساب والقاعدة المستخدمة: `python -m scripts.bootstrap_team --email manager@example.test --status`. لاستعادة كلمة مرور حساب موجود من طرفية مسؤول الخادم: `python -m scripts.bootstrap_team --email manager@example.test --reset-password`. يطلب الأمر كلمة المرور الجديدة وتأكيدها دون عرضهما، ويطبق سياسة كلمة المرور، ويلغي جميع جلسات الحساب ويسجل الاستعادة كإجراء مسؤول محلي. لا يعيد تفعيل حساب معطل ولا يغيّر دوره أو فريقه أو MFA أو الأدلة. لا توجد نقطة HTTP عامة لهذه الاستعادة، ولا يعاد إنشاء فريق بديل عند غياب الحساب. تبقى قيود محاولات تسجيل الدخول فعالة.

للتجربة بعد تحميل البيئة المناسبة، ابن خدمة التحليل المحلية المعزولة وشغلها مرة واحدة، ثم شغّل الخادم:

```bash
docker build --target analysis -t socify-v4-analysis .
bash scripts/start_v4_analysis.sh
export SOCIFY_ANALYSIS_SOCKET=/tmp/socify-v4-dev-analysis-ipc/analysis.sock
python run.py
```

الخدمة مستقلة بلا شبكة أو قاعدة بيانات أو مفاتيح الشركة، وتستخدم seccomp وحدود موارد وملفات مؤقتة تمسح بين الأعمال. في النواة التي لا تدعم Landlock يلزم backend المعزول الفعلي؛ لا تفعّل marker عزله على مضيف عادي. يشرح هذا الدليل إعداد خدمة التحليل وإعادة تشغيلها مع الحفاظ على البيانات والمفاتيح.

افتح `/cases` بعد الدخول. أنشئ قضية بالعنوان والسبب والهدف، ثم استخدم أقسامها السياقية. لا تستخدم `/lab` أو `/scores` أو APIs تدريب عامة؛ متقاعدة في وضع التشغيل. توافق التدريب داخل الاختبارات فقط، مع استمرار اختبارات V2 لتجنب فقد السلوك/البيانات التاريخية.

## عامل الاستيراد

PCAP وPCAPNG يعالجان عبر عامل منفصل حتى في التطوير؛ في الإنتاج توضع جميع الاستيرادات في الطابور. شغّل العامل في طرفية خدمة ثانية بعد تحميل **نفس قاعدة البيانات ونفس مفاتيح الجلسة/التشفير** المستخدمة بالخادم:

```bash
python -m scripts.run_import_worker --lease-seconds 120
```

خدمة `import-worker` موجودة في Compose وتشارك Volume القاعدة ومفاتيحها. لا يعني وصول الملف إلى حالة `queued` أنه حُلّل؛ تظهر الحالة والعدادات والأخطاء داخل القضية. التحليل الشبكي الحالي metadata لحزمة واحدة دون التقاط حي أو فك TLS أو إعادة تجميع TCP؛ DNS المضغوط وSNI المشفر/المجزأ قد لا يُستخرجان.

قائمة السجلات مرقمة من الخادم وبحثها مفهرس باستخدام SQLite FTS5. التصدير الحالي بحد 100000 سجل لكل طلب، ويلتقط قائمة المعرفات قبل البث ثم يقرأها باتصال مستقل للقراءة فقط. النسخة المحجوبة تستخدم سياسة `metadata_only_v1` فتزيل النصوص الحرة والمعرفات الحساسة؛ ليست نسخة تحقيق كاملة. النسخة غير المنقحة وتنزيل الأصل يتطلبان صلاحية `evidence.download` مستقلة.

## حدود البيانات

Codespaces لتطوير الكود والبيانات الاصطناعية فقط. نشر وتحليل بيانات الشركة يكون داخل بنيتها المعتمدة. حظر APIs الخارجية في التطبيق لا يغني عن منع خروج الشبكة من الحاويات والعمال ومحرك التقرير في بيئة الشركة.

لا تنقل سجلات شركة أو عينات أو نسخ قاعدة أو تقارير إلى GitHub أو إلى أدلة الاختبارات. تتبع نتيجة فحوص العزل والأداء على بيئة ممثلة؛ لا تُعامل نتائج fixture صغيرة كاختبار تحميل إنتاجي.
## النشر المؤسسي وعزل الخدمات

يشغّل `python run.py` العمال الثلاثة مع الخادم ومفاتيح التطوير المحفوظة، ولا يغير قاعدة `socify.db` الجذرية الموجودة. التشغيل الإنتاجي يبقى عبر Gunicorn وCompose ومفاتيح دائمة منفصلة عن بيئة التطوير.

يضم Compose مدخل NGINX داخلي النشر، وخدمة التطبيق على شبكة داخلية بلا default route، وعمال import/autopsy/playbook على `network_mode: none`. مدخل HTTP وحده ينشر `127.0.0.1:${SOCIFY_HTTP_PORT:-5000}` ولا يتلقى volume قاعدة القضية أو مفاتيحها. يلزم تطبيق TLS وسياسة الخروج على مدخل الشركة؛ لا تعادل الشبكة الداخلية وحدها عزل كل بيئة الشركة.

إذا كانت بيئة البناء تتطلب CA مؤسسية، يدعم Dockerfile secret اختياريًا اسمه `build_ca` يحتوي **شهادة الثقة العامة**، لا مفتاحًا خاصًا. تمرر بمثال `docker build --secret id=build_ca,src=/path/to/trusted-ca-bundle.pem --target runtime .`؛ لا تُضمّن الشهادة في الصورة ولا يُعطل التحقق من TLS. لا تحفظ بيانات proxy أو مفاتيح الشركة في المستودع.

التحليل الساكن لا ينفذ العينات. توجد علامة EICAR اصطناعية للاختبار، ويمكن للمدير نشر حزم YARA محلية ثابتة بعد أمثلة إيجابية وسلبية ومصدر وترخيص وبصمة، وفحصها في الخدمة المعزولة. مكتبة TI/GeoIP وSigma subset محلية؛ تُرفض الصيغ والمؤثرات غير المدعومة صراحة، ولا يحدث إثراء شبكي. راجع حدود عزل العامل ومكتبة القواعد وبقية شروط القبول في [دليل 2026-10-25](qa/v3-investigation-local-analysis-2026-10-25.md) قبل أي بيانات فعلية. اختبارات CI وCodespaces تستخدم بيانات اصطناعية.


## Health وMonitoring

- `/health/live`: العملية تعمل ولا يكشف بيانات حساسة.
- `/health/ready`: اتصال DB وschema version.
- `/api/health`: بعد المصادقة يعرض import jobs قيد العمل وإخفاقات القواعد وإصدار ATT&CK.
- كل Response يعيد `X-Correlation-ID` وتكتب أخطاء الخادم نوع الخطأ فقط بلا payload أو secret.

راقب زمن الاستجابة ومعدل 5xx وحجم/WAL القاعدة وjobs في `processing` و`failed_evaluations` وتأخر استهلاك outbox.

## عامل الاستجابة المحاكية

في الإنتاج تكون `SOCIFY_PLAYBOOK_INLINE_EXECUTION=0`، وتضيف API التشغيل إلى قائمة محفوظة. يشغّل Compose خدمة `playbook-worker`، أو شغّلها مستقلًا:

```bash
python -m scripts.run_playbook_worker --database instance/socify.db
python -m scripts.run_playbook_worker --database instance/socify.db --once
```

يعرض `/api/health` أعداد queued/running/failed وleases المنتهية. يسترد العامل أي تشغيل انقضت مدة ملكيته، وينفذ أثر كل خطوة مع تحديث حالتها في transaction واحدة. الفشل القابل للإعادة ينتظر backoff أسيًا حتى `retry_limit`. الإلغاء أثناء التنفيذ يضع طلبًا محفوظًا ويفحصه العامل قبل الأثر التالي. اضبط `SOCIFY_MAX_PENDING_PLAYBOOK_RUNS` لتحديد backpressure، ولا تشغّل inline في الإنتاج.

يعمل استيراد الإنتاج بالطريقة نفسها عبر خدمة `import-worker`، ويستأنف من checkpoint ذري كل 100 سجل:

```bash
SOCIFY_DATABASE=instance/socify.db python -m scripts.run_import_worker
SOCIFY_DATABASE=instance/socify.db python -m scripts.run_import_worker --once
```

استخدم مفتاح الاعتماد نفسه الذي شفّر دليل الرفع. يعرض `/api/health` queued/processing/failed وleases المنتهية. يحدد `SOCIFY_MAX_PENDING_IMPORT_JOBS` backpressure، ويجب أن تبقى `SOCIFY_IMPORT_INLINE_EXECUTION=0` في الإنتاج.

## النسخ الاحتياطي

```bash
python scripts/backup.py backups/socify-$(date +%Y%m%d).db --source instance/socify.db
python scripts/migrate.py --database instance/socify.db --dry-run
```

تستخدم الأداة SQLite Online Backup API وتفحص `integrity_check` وforeign keys. خزّن الناتج مشفرًا وبصلاحيات محدودة واختبر الاستعادة خارج مسار الإنتاج.

تحقق من `/health/ready` وعدد users/events/alerts/cases وتقارير audit قبل تبديل المسار. احتفظ بالقاعدة القديمة إلى نهاية التحقق.

## ترقية ATT&CK والرجوع

حمّل نسخة MITRE Enterprise STIX محفوظة محليًا مع اسم إصدار صريح. يرفض الأمر الحزمة الناقصة افتراضيًا، ويحسب SHA-256، ويحفظ الإصدار دون تعديل الإصدارات السابقة، ثم يفعّله ذريًا:

```bash
python -m scripts.load_attack_snapshot enterprise-attack.json --version 20.1 --database instance/socify.db
python -m scripts.load_attack_snapshot --activate-version 20.0 --database instance/socify.db
```

راجع `GET /api/attack/catalogs` وسجل `attack_catalog_transitions` بعد الترقية. لا تعِد استخدام اسم إصدار لمحتوى مختلف؛ يرفضه النظام بدل الكتابة فوق الدليل السابق.

## Rollback التطبيق

ابنِ image سابقًا من commit SHA موثق، أوقف الجديد، أعد Volume إلى نسخة متوافقة عند وجود migration غير عكوسة، شغّل readiness ثم أعد توجيه Proxy. الإصدار الحالي يدعم migrations إضافية forward-only؛ لا توجد أداة downgrade آلية ويجب ألا يدّعي CI خلاف ذلك.

## تشخيص التحليل والتنافس

المقبس `analysis.sock` يملك صلاحيات `0660`؛ يجب أن تتطابق هوية المستخدم/المجموعة بين الخادم والعميل. يبقى حجم IPC للعميل للقراءة فقط، ويُقفل مجلد الخدمة قبل استقبال الأعمال. تركيب الحجم `ro` لا يمنع اتصال UNIX socket بحد ذاته؛ لا تحوله إلى `rw` لمعالجة خطأ صلاحيات دون تشخيص.

يعيد العميل محاولة **الاتصال فقط** ثلاث مرات بعد 100 ثم 200 ثم 400ms عند غياب المقبس أو رفض الاتصال، ثم يفشل برسالة محددة. لا يُعاد إرسال طلب وصل إلى الخدمة. افحص `docker compose logs analysis` وهوية الحاويات وصلاحية inode عند رفض الإذن؛ لا تنسخ مفاتيح التطبيق إلى خدمة التحليل.

يتطلب التحليل المحلي Linux وprocfs وseccomp وعزل الملفات. على مضيف غير مدعوم، شغّل هدف Docker المخصص واضبط `SOCIFY_ANALYSIS_SOCKET`. يبقى التحليل fail-closed عند تعذر العزل؛ لا يوجد fallback غير معزول. لا تضبط علامة الحاوية المعزولة على عملية مضيف عادية.

تستخدم القواعد الملفية WAL، و`busy_timeout=15000`، ومفاتيح خارجية مفعّلة. تظل حجوزات العمال بمعاملات `BEGIN IMMEDIATE` قصيرة؛ يخفف عامل الاستيراد والتحليل الانتظار عند تنافس الحجز. لا تستخدم filesystem شبكيًا غير متوافق مع WAL، واحتفظ بملفات القاعدة/WAL معًا عند صيانة الملفات؛ أداة backup تستخدم SQLite Online Backup.

حدود البريد: 2MiB، عمق MIME حتى 5 (الجذر عمق 0)، 100 جزء، 200 رأس و25 مرفقًا. تُفحص الحدود قبل فك payloads. يُحفظ الأصل مشفرًا وببصمته؛ أسماء العرض آمنة وتحتفظ بالامتداد، والأسماء غير القابلة للتحويل تستبدل باسم مشتق من SHA-256. أسماء العميل لا تستخدم مسارًا للتخزين. تُرفض DTD والكيانات الخارجية في XML حتى مع مقدمة طويلة أو ترميز UTF-16.
