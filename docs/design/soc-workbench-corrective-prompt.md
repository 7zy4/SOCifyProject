# SOCify V3 — البرومبت التصحيحي الشامل / SOC Workbench Corrective Prompt

الإصدار: 2026-10-27. المرجع الحاكم: طلب المستخدم الحالي وصورة LetsDefend المرفقة. الفرع الوحيد: `socify-version-3`. تُكتب هذه المواصفات قبل تعديل كود التطبيق، ثم تُطبّق وتُختبر. تحل محل وصف سطح المكتب في البرومبت السابق. لا فرع جديد ولا force-push ولا إعادة تهيئة قاعدة البيانات.

## 1. تعريف المشكلة والنتيجة / Problem and outcome

المشكلة الأولى: نُفذت المنصة كبيئة Windows بنوافذ متداخلة وسطح مكتب ومجلدات وشريط مهام؛ هذا يخفي المحتوى ويجعل أدوات التحقيق تعتمد على ترتيب النوافذ. المشكلة الثانية: توزيع المزايا لا يطابق رحلة محلل SOC ولا يوضح ما يتيحه الدور أو نطاق القضية. المطلوب إعادة هندسة التنقل والصفحات والتدفقات، لا تغيير الألوان فقط.

صمّم مركز عمليات SOC متماسكًا يتبع تكوين LetsDefend في الصورة: شريط علوي ثابت، تنقل جانبي ثابت، مساحة رئيسية واسعة، قنوات Main Channel / Investigation Channel / Closed Alerts، جدول تنبيهات كثيف وواضح، وتفاصيل تُفتح عند الطلب. حافظ على SOCify كعلامة نصية أصلية، وعلى البيانات والأمان والتقارير الفورية. تطابق تنظيم المرجع لا يعني انتحال علامة LetsDefend أو استيراد بيانات تدريبه أو إضافة أقسام تسويق ودفع لا يحتاجها المنتج.

## 2. البحث والمهارات / Research and skills

شغّل أمر المستخدم حرفيًا `npx skills use "https://github.com/vercel-labs/agent-browser" --skill "agent-browser"`، واحفظ مخرجاته واقرأها كاملة. عند تعذر الكتابة في cache الافتراضي، استخدم cache داخل work دون تعديل HOME. اقرأ core من CLI الفعلي، واستخدم جلسة مسماة، snapshots بعناصر @ref، وانتظار حالة محددة بدل sleep عشوائي. طبّق dogfood في مرحلة المعاينة من منظور مستخدم، واربط الملاحظات بدليل قابل لإعادة الإنتاج. حل مسارات supporting files داخل `skill-data` الخاص بالحزمة، لا داخل الريبو عشوائيًا. لا تعطل TLS للوصول إلى مرجع.

استفد من مصادر أولية منشورة: [LetsDefend official documentation](https://letsdefend.io/blog/incident-response-edition-documentation)، [Carbon data table guidelines](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines)، [GitLab Pajamas layout](https://design.gitlab.com/product-foundations/layout/)، و[Vercel Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines). راجع أيضًا web-design-guidelines قبل إغلاق التنفيذ. هذه أنظمة تصميم موثقة، وليست شهادة أن أي جزء منها لم يستخدم AI. اجعل كل قرار يخدم مهمة مستخدم محددة، مع أولوية للصورة الحالية في التكوين.

## 3. نطاق المنتج / Product scope

SOCify منصة تشغيل وتحقيق وأدلة؛ لا تحوّلها إلى موقع دورات أو ألعاب. أعد استخدام الاستيراد والكشف المحلي وYARA وSigma والمؤشرات والتحقيق والاستجابة والمهام والتقارير. أضف الوصول المنظم والوظائف الناقصة التي تجعل هذه الوحدات رحلة متصلة. لا تضف زرًا بلا خدمة حقيقية ولا بيانات إنجاز أو تنبيهات وهمية في قاعدة المستخدم.

| الميزة | الحالة قبل التصحيح | التنفيذ المطلوب |
|---|---|---|
| Monitoring | الكشف والتنبيهات داخل القضية، لا قائمة SOC مشتركة | قائمة تنبيهات حقيقية عابرة للقضايا المصرح بها؛ قنوات وفرز وفلاتر وتفاصيل وروابط التحقيق |
| Log Management | موجود داخل قسم السجلات | مدخل مستقل مع اختيار قضية واضح ثم أداة السجلات الأصلية وبحثها واستيرادها |
| Case Management | موجود مع عرض مجلدات سطح مكتب | جدول قضايا واضح، بحث وترقيم، إنشاء وإسناد وتبويبات داخلية ثابتة |
| Endpoint Security | سجلات أصول موجودة | جرد أصول القضية، النظام والعنوان والدور والتقييم؛ إضافة/تحرير بحسب الصلاحية وربط الاستجابة |
| Threat Intel | مؤشرات وإثراء محلي موجودان | صفحة سياقية للمؤشرات والإثراء ونتائجها؛ إدارة الحزم في المكتبة للدور المصرح فقط |
| Email Security | لا محلل رسائل EML مخصص | رفع EML إلى الحجر المشفر الحالي، تحليل MIME آمن للرؤوس والنص والروابط والمرفقات وبصماتها، وحفظ نتيجة مرتبطة بالدليل |
| Sandbox | حجر وتحليل ساكن موجودان | مدخل واضح لتحليل العينات المحلي مع حالته ونتائجه؛ اذكر أنه ساكن، ولا تدّعِ sandbox ديناميكي أو تحكمًا حيًا بالأجهزة |
| Reports | إصدارات ومهام وإخراج خمس صيغ موجودة | صفحة تقارير مرتبطة بالقضية، زر تقرير فوري من رأس القضية، والحفاظ على الطابور والتحديث والمراجعة والاعتماد |
| Tasks / Playbooks / Team / Library / Profile | موجودة | ترتيبها كمساندة للعمل اليومي، بقوالب موحدة وأفعال متوافقة مع الصلاحيات |

لا يُشترط استنساخ خدمات EDR أو بث بريد أو تشغيل برمجيات خبيثة حية لتنفيذ تشابه تجربة LetsDefend. تعرض أدوات SOCify قدراتها الحقيقية وحدودها بوضوح، مع إمكانية إضافة تكاملات منفصلة لاحقًا بعقود أمانها.

## 4. البنية المعلوماتية / Information architecture

الشريط العلوي: كلمة SOCify النصية، تنقل رئيسي حقيقي Operations / Cases / Reports، ثم المظهر واللغة والحساب والخروج. لا XP أو كأس أو تسعير أو صفحة Learn فارغة. الشريط الجانبي يحتوي مجموعة التحقيق بالترتيب: Monitoring، Log Management، Case Management، Endpoint Security، Threat Intel، Email Security، Sample Analysis / Sandbox. يليها مساندة التحقيق: Reports، My Tasks، Playbooks، Analysis Library، Team. الملف والأمان متاحان من الحساب، والتدقيق/الإدارة لا يظهران إلا بصلاحياتهما.

المسارات الجديدة `/monitoring`، `/log-management`، `/endpoint-security`، `/threat-intel`، `/email-security`، `/sandbox`، `/reports`. احتفظ بـ`/cases` و`/cases/<id>?tab=...` وكل الروابط القديمة المفيدة. لا تُعد `/lab` أو `/scores` التدريبية. يجوز إبقاء redirect `/dashboard` إلى `/cases` للتوافق؛ العمليات لها رابط Monitoring واضح. لا تغيّر redirect الدخول بما يكسر العملاء الحاليين بلا حاجة.

الأدوات التي تحتاج سياقًا تعرض اختيار قضية مصرح بها قبل أي تحميل تفصيلي. معامل URL `case_id` هو المصدر للحالة؛ لا تخمّن أن آخر قضية مسموح بها هي قضية المستخدم المقصودة. يدعم الاختيار البحث والترقيم حتى لا تكون القضايا بعد أول 25 غير قابلة للوصول. عند فتح أداة من قضية، حافظ على معرفها والمرجع والعنوان المختصر وأزرار العودة وفتح التحقيق والتقرير. روابط القائمة تحفظ القضية الحالية في أدوات التحليل، ولا تعرض بياناتها عند انتهاء الصلاحية. القارئ ذو نطاق دفعات محدود يرى السجلات المصرح بها، ولا يتسرب إليه سياق التحقيق أو التقارير أو المؤشرات المجمعة.

## 5. توزيع الأدوار / Roles and permissions

المرجع هو `permissions` الفعلية من `/api/auth/me` مع overrides الدور، وليس اسم الدور المعروض وحده. احترم عضوية القضية، مساحة العمل، صلاحيات دفعات الاستيراد، وصلاحية تنزيل الأصل. لا تغيّر النموذج الأمني الافتراضي لمجرد شكل المرجع.

| الدور النموذجي | أولوية الاستخدام | المسموح عرضه/تنفيذه |
|---|---|---|
| L1 / Analyst | الفرز والسجلات | قراءة القضايا المصرح بها، البحث، الأدلة، مراجعة التنبيه عند السماح؛ لا اعتماد تقارير أو إدارة المستخدمين |
| L2 / Responder | التحقيق والاستجابة | الأدوات السابقة والاستجابة والتصعيد وتوثيق النتائج بحسب صلاحيات القضية؛ التنزيل الخاص يحتاج إذنًا مستقلًا |
| Investigator | الربط والتسلسل | الأصول والمؤشرات والفرضيات والأسباب والخط الزمني، ورفع الأدلة المصرح به |
| Reviewer / Auditor | القراءة والمراجعة | معلومات القضية المصرح بها؛ أفعال التعديل لا تظهر دون إذن؛ اعتماد التقرير للمراجع ذي reports.approve فقط |
| SOC Manager | توزيع ومراجعة | إدارة أعضاء القضية والإسناد والصلاحيات الممنوحة، إدارة المكتبات بحسب أذوناتها، واعتماد التقارير |
| Admin | إدارة المنصة | إذن * مع حدود مساحة العمل والتحقق من المورد |

أظهر الأفعال بموجب إذنها: `cases.create` للإنشاء، `cases.update` للتحرير والانتقال، `evidence.add` للرفع، `cases.assign` للإسناد الإداري، `reports.approve` للاعتماد، `evidence.download` للتقرير الكامل، و`samples.download` لتنزيل الأصل المحجور. لا تمنح التنزيل لمجرد إمكان عرض ملخص التحليل. لا تفرض فصلًا اصطناعيًا بين L1/L2 إذا كان الإذن الفعلي يسمح لكليهما؛ قد يحتفظان بأذونات متساوية افتراضيًا ويختلفان بالمسؤولية وسير العمل.

إخفاء الأزرار تحسين للتجربة؛ يجب رفض الرابط المباشر والطلب المصطنع في الخادم أيضًا. عند حالة read-only اشرح السبب باختصار. عند منع النطاق أعطِ مسارًا إلى السجلات أو قائمة القضايا دون كشف أسماء/أعداد غير مصرح بها.

## 6. التصميم المرجعي / Layout specification

زاوية العرض أمامية مسطحة، تطبيق ويب كامل. لا نوافذ عائمة ولا مقابض تحجيم ولا تصغير/تكبير ولا شريط مهام ولا مجلدات سطح مكتب ولا ورقة dossier مركزية. احذف ملفات مدير النوافذ والأصول والاختبارات الخاصة به واستبدلها باختبارات البنية الجديدة.

عند عرض 1440px: الشريط العلوي 76px، الشريط الجانبي 240px تقريبًا، المحتوى يبدأ بعده مع حشوة 32px. العرض سائل بلا عمود فارغ كبير. الشريط الجانبي يبدأ أسفل الشريط العلوي ويُمرّر مستقلًا عند الحاجة. عند RTL يكون الشريط في اليمين، وتتبع الجداول وتسميات الأفعال الاتجاه المنطقي. لا تعكس مسار الملف أو البصمة أو IP. عند 1280px الحشوة 24px؛ تحت 1100px تتحول القائمة إلى درج قابل للفتح والإغلاق؛ عند 390px الحشوة 16px والتنقل الرئيسي مدمج والترويسة تسمح بالتفاف مدروس.

القائمة الجانبية: صف 44–48px، أيقونة خطية واحدة 20px، تباعد 12px، نص 14px، مجموعة نشطة بخلفية زرقاء هادئة وعلامة واضحة. لا أيقونات عشوائية لكل بطاقة. يظهر المسار الحالي بـaria-current. دعم انهيار القائمة على سطح المكتب اختياري إذا لم يعقّد القراءة؛ درج الجوال إلزامي مع Escape وإرجاع التركيز ومنع عناصر القائمة المغلقة من التبويب.

ترتيب Monitoring من أعلى لأسفل: عنوان ووصف سطر واحد وفعل إنشاء قضية؛ قنوات ثلاث بعرض واضح مستوحاة من ألسنة المرجع المائلة بخلفية هادئة؛ أعداد حقيقية صغيرة؛ شريط بحث وفلاتر وفرز وتحديث؛ جدول التنبيهات؛ ترقيم في الأسفل. لا تضع 6 بطاقات KPI قبل الجدول. التبويب النشط أزرق والنص عالي التباين، والتبويبات الأخرى محايدة. رابط تبويب حقيقي مع URL وaria-current صالح إن كان التنقل يعيد تحميل الصفحة؛ لا تستخدم role=tab دون تطبيق سلوكه كاملًا.

أعمدة الجدول: التوسيع، الخطورة، وقت الاكتشاف، اسم القاعدة/السبب، معرف التنبيه، مرجع القضية وحالتها، المسؤول، الإجراء. لا تسمّ معرف التنبيه Event ID إذا كان مختلفًا عن معرف السجل؛ أظهر Evidence Event IDs داخل التفاصيل. كل صف 64–76px عند البيانات المعتادة، والاسم يسمح بسطرين أو أكثر عند الضرورة. التاريخ والبصمة والمعرفات معزولة LTR. صف التفاصيل يعرض السبب والحكم وحالة المصدر وروابط الأدلة والتحقيق والتقرير. زر التوسيع native مع aria-expanded/controls، ولا تتطلب البيانات hover فقط.

الصفحات الثانوية: رأس عنوان وفعل أساسي واحد غالبًا، ثم سياق القضية، ثم محتوى الأداة. نموذج إنشاء/استيراد طويل يفتح عند الطلب بدل أن يدفع النتائج خارج الشاشة. لا تخفِ كل التحليل داخل نوافذ dialog؛ الحوار لمهمة قصيرة أو تأكيد فقط. الرأس الداخلي للقضية يحتوي مرجعًا وحالة وخطورة وعودة وتقريرًا فوريًا، تليه تبويباتها الأساسية ثم المحتوى. حافظ على edit panels القابلة للفتح ومسودة النماذج الموجودة.

## 7. الهوية البصرية والخطوط / Visual system

الهوية SOCify: أزرق واحد للتفاعل مع كحلي وفحمي ومحايدات. اللون التركوازي في المرجع ليس إلزاميًا للعلامة. لا gradients مزخرفة، لا glassmorphism، لا توهج ولا رسومات سايبر عامة ولا صور stocks ولا بطاقات متكررة بلا وظيفة. الزوايا 6px للحقول والأزرار و8px للحاويات؛ الحدود 1px؛ الظل للحوار والدرج فقط.

لوحة Light: background #F4F6FA، surface #FFFFFF، secondary #EEF2F7، text #142B49، muted #52617A، border #D5DCE7، action #255DD9، primary hover #1C49B1. لوحة Dark: background #0D101B، surface #171E2A، secondary #1D2736، text #EFF3FA، muted #A9B6CB، border #344258، action #98B6FF، primary fill #315CCC. Critical/error #B4232D في الفاتح و#FFB4B9 في الداكن؛ High #8C5100 / #EFC278؛ بقية الحالات محايدة أو زرقاء مع نص مكتوب. لا تستخدم اللون وحده للخطورة/الحالة. التفاصيل النهائية تُحفظ في `design-tokens.json` ومنها CSS مولد.

العربية Almarai 400/700 فقط، والإنجليزية IBM Plex Sans 400/500/600/700 فقط؛ WOFF2 محلية مع OFL. لا عائلة ثالثة ولا خطوط أيقونات. الأساس 14px، الجداول 14px، Label 13–14px، Metadata 12px، H1 داخلي 26px، H2 20px، H3 16px، كلمة العلامة 28px. العربية line-height 1.8، الإنجليزية 1.6، العناوين 1.4–1.5، tracking العربية صفر. استخدم tabular-nums وfont-synthesis:none. لا تجعل صفحات الجدول ذات أرقام صغيرة مفرطة كما في لقطة المرجع المصغّرة.

العربية والإنجليزية لغتا نصوص المنتج فقط. لا تترجم السجلات والأدلة وأسماء المستخدمين أو الملفات ولا تستبدلها. حافظ على اختيار اللغة والثيم؛ System/Light/Dark يحسم في head قبل CSS مع storage fallback ومزامنة تغير النظام. طبّق الهوية نفسها على الدخول والتسجيل والصفحة التعريفية والتقارير الجديدة؛ التقارير المطبوعة فاتحة. الشعار نص SOCify فقط. لا تعِد اللوقو المصوّر القديم.

## 8. عقد قائمة التنبيهات / Monitoring API contract

أضف blueprint تشغيليًا باسـم يبدأ `autopsy` كي يمر من حدود المنتج الحالية، وواجهة GET `/api/soc/monitoring`. مدخلات مضبوطة: channel في main/investigation/closed، page موجب محدود، page_size حتى 50، q حتى 200 حرف، severity من القيم الأربع، mine كـ0/1، sort من قائمة ثابتة وdirection في asc/desc. كل قيم SQL مربوطة، وأسماء الفرز من allowlist فقط.

اجمع التنبيهات التي تملك owner_case_id صالحًا فقط، مع workspace الصحيح وقضية غير مؤرشفة وعضوية القضية وtraining scope للتوافق. استبعد سياق القضية الكامل من كل القوائم والأعداد عند نقص وصول الدفعات؛ استخدم دالة نطاق مشتركة تحقق نفس case_full_access ولا تستنتج الصلاحية من بيانات المتصفح. لا N+1 لكل تنبيه. حساب القنوات مرتبط بالحالة الفعلية للقضية: main للحالات new/open/triaged، closed للحالات closed/cancelled، investigation لما سواها. اشرح هذا الربط في الواجهة؛ ليست القنوات نسخًا جديدة من الحالات ولا تغلق التنبيه مستقلًا عن شروط القضية.

ترجع النتيجة items وtotal وpage/page_size وcounts للقنوات الثلاث ضمن البحث والفلاتر والصلاحية نفسها، ووقت جلب حقيقي. عناصر الصفحة تُرجع حقول العرض اللازمة فقط، لا raw evidence واسعًا أو نصوصًا خاصة. التفاصيل تُقرأ من endpoint القضية المصرح به عند التوسيع، أو من حقول metadata المسموح بها. لا تحوّل نتائج أول صفحة إلى العدد الكامل.

إجراء التحقيق يفتح القضية الحالية، ومراجعة التنبيه تستخدم endpoint المراجعة الموجود بإصداره وسبب تغييره. الإسناد من إدارة مسؤوليات القضية وصلاحيتها؛ لا زر يستولي على قضية بمخالفة العضوية. تبقى دورة الإغلاق الرسمية، والمراجعة المعتمدة والأدلة اللازمة، كما هي.

## 9. عقود الأدوات / Tool workflows

Log Management يعيد استخدام أداة السجلات والاستيراد الموثوقة ويحافظ على q/page/job_id والوقت والمنطقة الزمنية ونطاق الدفعات. Endpoint Security يعرض asset records ويمكن إضافة أصل أو تحريره إذا can_update؛ رابط توثيق الاستجابة يفتح response بالقضية نفسها؛ لا يعرض isolate device ناجحًا دون تكامل حي. Threat Intel يعرض indicator records وobservables والإثراء الموجود؛ verdict المصدر ليس استنتاجًا نهائيًا.

Email Security: ارفع .eml عبر آلية samples الحالية لتشفير الأصل وحفظ SHA-256 والدليل والحيازة؛ بعد ذلك اسمح بتحليل الرسالة المحجورة فقط داخل قضيتها. endpoint جديد يقرأ العينة بموجب صلاحيات الأصل/الأدلة المناسبة، يتحقق من البصمة، الحجم الأقصى 2MiB وعدد أجزاء MIME والرؤوس والمخرجات. لا تُنفذ HTML أو JavaScript، لا تُحمّل صورًا خارجية، لا تُفتح روابط، لا تُفك أرشيفات مرفقات ولا تُنفذ ملفًا. أعد From/To/Reply-To/Subject/Date/Message-ID/Authentication-Results كنص مصدر، body text آمن، URLs كنص خام بلا روابط قابلة للفتح، وقائمة مرفقات filename/type/size/SHA-256. بيّن أن Authentication-Results رأس غير موثق قد يُزوّر، ولا يُعد تحقق SPF/DKIM من الخدمة. HTML-only يتحول إلى نص مرئي دون تحميل موارده. لا توجد نتيجة clean تلقائية لغياب مؤشر.

احفظ نتيجة التحليل كسجل analysis مرتبط بـevidence_id وبطريقة وملاحظات حدود واضحة، لتدخل التقرير الفوري. منع الحفظ في closed، منع التكرار غير الضروري، وعمليات القراءة والتحليل لا تمنح samples.download ضمنيًا. امنع إرجاع raw bytes أو أجزاء base64 من API التحليل. اختبر malformed MIME/oversize/HTML/XSS/attachments/binary charset والعضوية والدفعات وسحب الوصول.

Sandbox / Sample Analysis يستخدم الحجر والفحص الساكن الحاليين وحالات المهمة الفعلية وYARA المسموح بها ونتائجها، دون إضعاف العزل. الأدوات المستقلة تعيد التوجيه/العودة إلى القضية بعد الحفظ، مع بقاء السياق وعدم ازدواج قاعدة البيانات.

## 10. التقارير الفورية / Immediate reporting

حافظ على خمس صيغ PDF/DOCX/HTML/MD/JSON، وعلى snapshots وإصدار المصدر والبصمة وسياسة المشاركة والمراجعة والاعتماد والتاريخ السابق. أضف فعل تقرير فوري واضح في رأس القضية وصفحة Reports؛ يبدأ POST التقرير الموجود دون الانتقال إلى صفحة إعدادات طويلة، ثم يظهر الطابور والتقدم والنتيجة وأزرار التنزيل عند اكتمالها. لا تصف PDF جاهزًا وهو ما زال في الطابور. اختر full فقط لمن يملك evidence.download وإلا metadata_only_v1، مع توضيح السياسة. لا تنشئ تقريرًا تلقائيًا عند مجرد فتح الصفحة.

امنع النقر المكرر أثناء الطلب، وأظهر 409 بطلب تحديث الحالة دون فقد النموذج، و429 برسالة انتظار، و401 بعودة الدخول، والفشل باسم المهمة وخيار إعادة المحاولة الموجود. مؤقت التحديث لا يتكرر بعد مغادرة الصفحة ولا يشغل طلبات متوازية غير محدودة. اجعل الاعتماد منفصلًا عن التوليد، ولا يفتح الزر القضية المغلقة ولا يتجاوز شروط إغلاقها.

## 11. سلامة التطبيق والأداء / Engineering

ابق على Flask/Jinja وvanilla JS/CSS؛ لا ترحيل إطار لمجرد التصميم. افصل soc-workbench.js عن أدوات autopsy الحالية. أزل تحميل desktop.js/window-controls.js وواجهتهما، وأزل عرض المجلدات الذي كان متعلقًا بسطح المكتب. استخدم HTML أصليًا وجداول حقيقية وروابط للتنقل وأزرارًا للأفعال. لا innerHTML لمدخل المستخدم. حافظ على CSP/CSRF وRBAC/BOLA وعزل التحليل وتشفير العينات والنسخ المعتمدة.

كل endpoint يتحقق من المورد قبل تقديم تفاصيله، ويعود 404 عند غياب صلاحية المورد حسب سياسة التطبيق. طبق حدود الحجوم والعدد والوقت على أي تحليل جديد. لا أذونات عامة جديدة أو تغيير كلمات مرور أو seed تلقائي. لا worker بديل غير معزول كحل اختبار. لا تضع sample credentials في الشيفرة الإنتاجية.

استخدم pagination، لا تُحمّل كل القضايا أو التنبيهات في المتصفح. الفرز والفلاتر والحالة من URL وتعمل بعد refresh/back/deep link. امنع سباق الطلبات أو تجاهل النتائج القديمة عند التغيير، وأظهر حالة loading معلنة. حافظ على المحتوى عند فشل إجراء، وعلى المسودة عند أخطاء الحفظ المعروفة. لا وميض ثيم ولا طلبات خطوط خارجية. حركات قليلة 120–180ms للشفافية/transform فقط، واحترام reduced-motion. لا transition:all.

## 12. الوصول والاستجابة / Accessibility and responsive behavior

WCAG AA حيث يمكن التحقق: تباين 4.5:1 للنص المعتاد، 3:1 للعناصر الكبيرة والحدود المهمة، تركيز واضح 2px، هدف لمس 44px على الأجهزة اللمسية، تسميات الحقول والأيقونات، aria-live للنتائج، skip link، headings متسلسلة. التبويب يصل إلى الأفعال بترتيب منطقي. الجداول الطويلة تمرّر داخل حاوية قابلة للتركيز ومسمّاة؛ لا overflow أفقي لجسم الصفحة. النص الطويل يلتف أو يتيح كشفه، ولا تقطع معرفًا دون الوصول إلى قيمته الكاملة. اختبر 200% zoom والجوال في RTL/LTR. لا تدّعِ شهادة وصول كاملة من axe وحده.

## 13. خطة التنفيذ والترتيب / Execution order

1. توثيق البحث وفجوة المزايا وهذه المواصفات قبل كود التطبيق.
2. تثبيت الرموز والخطوط والقالب والتنقل ومسارات الصفحات مع إزالة سطح المكتب.
3. بناء قائمة المراقبة المصرح بها وفحوص العد والترقيم والبحث والحالات والدفعات.
4. بناء اختيار القضية وروابط السياق وأدوات السجلات والأصول والمؤشرات والبريد والتحليل والتقارير.
5. إضافة EML الآمن والربط بالدليل، وزر التقرير الفوري والمحافظة على مسار إعداد الصيغ واعتمادها.
6. توحيد القوالب العامة والنماذج والحالات واللغة والثيم على المشروع.
7. اختبارات أمن وتكامل ثم مصفوفة متصفح ثم dogfood وتصحيح الملاحظات وإعادة الاختبارات المتأثرة فقط.
8. توثيق النتائج والحدود والمعاينات ثم commit/push مباشر إلى socify-version-3 مع تحقق رأس الفرع قبل وبعد.

## 14. بوابات القبول / Acceptance gates

- لا desktop windows/taskbar/folder view أو طلباتها في التشغيل. جميع روابط التنقل الجديدة تعمل ولا تعود إلى /cases بصمت.
- جدول Monitoring يتبع ترتيب المرجع وقنواته مع بيانات حقيقية، وحالة فراغ عند غياب التنبيهات.
- لا تسرب للأعداد أو المراجعات أو أسماء القضايا بين المستخدمين/المساحات/الدفعات، بما فيها الفلاتر والـCSV إن أضيف.
- البحث والترقيم والفرز والقنوات تعمل على نتائج الخادم وتُحفظ في URL. اختيار قضية بعد الصفحة الأولى متاح.
- المزايا والأفعال مرتبطة بالأذونات الفعلية، ومراجع read-only لا يرى تحريرًا، ومدير فقط يرى إدارة الإسناد عند إذنه، والروابط المباشرة محمية.
- EML يظل خامله، أصله مشفر وبصمته محفوظة ونتيجته تدخل التقارير؛ لا HTML نشط أو طلبات روابط أو صور خارجية.
- زر التقرير الفوري يبدأ نسخة محفوظة واحدة ويعرض المعالجة بصدق؛ الصيغ الخمس والمراجعة والاعتماد والنسخ السابقة سليمة.
- AR/EN × Light/Dark/System، وجميع الصفحات، عند 390/768/1280/1440 و200% zoom؛ لا أخطاء JS ولا مخالفات axe serious/critical في الحالات المختبرة.
- توليد الرموز متسق، JS syntax/CSS parse/Ruff/diff-check، واختبارات التوافق والأمان المناسبة تنجح.
- عند عجز البيئة عن Landlock أو Docker وثّق الاختبار المتعذر؛ لا تدّعِ نجاحه ولا تضعف العزل. اختبر render_files المباشر وقواعد API وحالات الطابور بصورة مستقلة.
- التسليم يتضمن البرومبت والبحث وخريطة المزايا والصلاحيات ومعاينات فعلية وتقرير تحقق. لا وعد بأن البرنامج خالٍ من كل عيب محتمل؛ عالج كل عيب قابل للإعادة ظهر في النطاق واذكر حدود التحقق.
